## Решение
### Общие решения по архитектуре
- завести новые подсистемы для реализации функций умного дома:
  - `smart-home-app` - подсистема интеграции с внешними системами умного дома, в том числе стриминг видео с домофонов в мобильное приложение;
  - `smart-home-db` - БД данных по интеграциям для `smart-home-app`;
- модернизировать инфраструктуру для внедрения повышения информационной безопасности и завести новые сервисы:
  - `tenant-api-gateway` внутренних пользователей (собственников и менеджеров);
  - `b2b-api-gateway` в качестве ingress/egress proxy для всех интеграций с партнерами (УК и системами умного дома);
  - `b2b-adapters` - слой адаптеров, отвечающих за функции безопасности, например, проверки схем передаваемых персональных данных, токенизацию, детокенизацию, маскирование, получение токенов OAuth2; для разных партнеров должны заводиться свои адаптеры;
- вынести хранение персональных и конфиденциальных данных в `token-vault`, где будут храниться пары ключ-зашифрованное значения;
- `vault-service` будет работать с `token-vault` и осуществлять аудит изменений токенов и секретов, а для хранения и управления ключами предлагается использовать `keys-manager`;

### Альтернативы

----

- переводить имеющихся персональные и конфиденциальные данные в `token-vault` не сразу, сначала использовать его только для новых функций умного дома;
- аналогично - использовать dummy адаптеры для управляющих компаний, постепенно наращивая функционал безопасности;

### Требования к безопасности
- использовать HTTPS TLS 1.2+ как для внутренних взаимодействий, так и для внешних;
- WSS вместо WS - (используется в мобильном приложении?);
- завести хранилище секретов и токенов, ротировать ключи шифрования (KMS/HSM);
- сократить контур обмена персональными и конфиденциальными данными во внутренней сети слоем адаптеров, в других случаях использовать токенизацию и маскирование;
- минимизировать, валидировать схемы данных и токенизировать сами данные для внешнего API;
- вести аудит изменений конфигураций, действий с секретами и ключами;
- маскирование секретов в логах;
- регулярный аудит ролей, автоматический отзыв ролей;

### Протоколы аутентификации и авторизации
Для взаимодействия по внешнему API с SmartEntranceSolutions (равно как и с другими партнерами):
- аутентификация через auth-service (keycloak): OAuth 2.0 client credentials + короткоживущие токены JWT;
- базовая авторизация в ingress proxy `b2b-api-gateway`;
- расширенная авторизация: реализация проверки RBAC или ABAC для сложной логики в `smart-home-app` или `tenant-core-app`;

### Взаимодействие между внутренними и внешними системами
- allowlist IP, rate limit, DoS защита для входящих запросов;
- HTTPS REST API c авторизацией и аутентификацией;
- согласование контрактов Open API;
- проверка схем данных перед отправкой, минимизация данных, маскирование, токенизация, детокенизация с помощью слоя адаптеров;
